# 底部菜单结构（以及为什么这么排）

微信小程序的 `tabBar` **最多 5 项**，硬性限制。所以「待办」和「作业」合并成
一项、「饮食 / 运动 / 体重」合并成「健康」，才腾出位置放健康页。

| 菜单项 | 页面 | 内容 |
| --- | --- | --- |
| 总览 | `pages/dashboard` | 工作台首页 + 全部功能入口 |
| 今日 | `pages/today` | 当天课表 / 待办 / 作业 |
| 课表 | `pages/courses` | 课程增删改 |
| 待办·作业 | `pages/tasks` | 分段切换：待办 / 作业 |
| 健康 | `pages/healthhub` | 分段切换：饮食 / 运动 / 体重 |

## 重要事项和设置没有底部入口

位置不够。这两个页面从 **总览 → 全部功能** 进，总览顶部的倒计时卡片、
指标卡也都能点进去。

## 合并页是怎么实现的

没有把两个模块的几百行逻辑复制进一个大文件（那样以后改一处要改两处，
且已经验证过的逻辑会分叉），而是让子模块保持原样、由 `utils/tabHost.js`
把它们的 `Page` 定义挂到同一个实例上：

- 子模块的 data 键加前缀并入宿主（`list` → `todos_list`）
- 子模块内部的 `this.data` / `this.setData` 走 Proxy 自动加前缀
- 方法一律带模块前缀（`todos_add` / `assignments_add`），
  子模块内部 `this.add()` 经 Proxy 解析到**本模块**的版本

**为什么要带前缀而不是留裸名字**：两个模块都有 `add` / `remove` / `toggle`，
裸名字只能属于其中一个，另一个模块内部调用就会串台 —— 这类 bug 很难查。

## 旧的独立页面还在

`pages/todos`、`pages/assignments`、`pages/diet`、`pages/run`、`pages/health`
仍然注册在 `app.json` 里，单独打开也能正常工作（已验证）。

保留它们是为了不让旧链接变死链：已经发布过的版本、用户从「最近使用」、
或者别的页面里写死的跳转路径，都可能直接打开这些地址。

它们同时也是合并页的子模块来源 —— 每个文件末尾都有
`module.exports = DEFINITION;`，`tabHost` 靠它拿到页面定义。
所以**不要删这几个文件**，删了合并页会直接报错。

## 跳转到合并页的指定分段

`wx.switchTab` 的 url **不能带 query**（带了会跳转失败），所以「打开健康页并
停在运动」这种需求只能：

1. 把 `{ url, seg }` 写到 `app.globalData.pendingSeg`
2. `switchTab` 过去
3. 目标页在 `onShow` 里取走并清除

总览的指标卡和「全部功能」格子都是这么做的（`goStat` / `goTab`）。
