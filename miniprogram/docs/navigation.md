# 底部菜单结构（以及为什么这么排）

微信小程序的 `tabBar` **最多 5 项**，硬性限制。5 个位置现在全用满了，
所以凡是「还想再塞一个进菜单」的需求，都必须先合并掉现有的某一项。

| 菜单项 | 页面 | 内容 |
| --- | --- | --- |
| 总览 | `pages/dashboard` | 分段切换：总览 / 今日 |
| 课表 | `pages/courses` | 课程增删改 |
| 待办·作业 | `pages/tasks` | 分段切换：待办 / 作业 |
| 健康 | `pages/healthhub` | 分段切换：饮食 / 运动 / 体重 |
| 设置 | `pages/settings` | 外观 / 备份 / 学期 / 作息表 / 目标 |

## 合并的来龙去脉

- **待办 + 作业 → 待办·作业**：腾出位置给「健康」。
- **今日 → 总览**：腾出位置给「设置」。原来的「今日」是独立一格，
  内容（当天课表 / 待办 / 作业）和总览高度重叠，并进总览做成第二段最省地方。

## 重要事项没有底部入口

位置不够。它从 **总览 → 全部功能** 进，总览里的倒计时卡片也能点进去。

## 合并页是怎么实现的

没有把两个模块的几百行逻辑复制进一个大文件（那样以后改一处要改两处，
且已经验证过的逻辑会分叉），而是让子模块保持原样、由 `utils/tabHost.js`
把它们的 `Page` 定义挂到同一个实例上：

- 子模块的 data 键加前缀并入宿主（`list` → `todos_list`）
- 子模块内部的 `this.data` / `this.setData` 走 Proxy 自动加前缀
- 方法一律带模块前缀（`todos_add` / `assignments_add`），
  子模块内部 `this.add()` 经 Proxy 解析到**本模块**的版本
- 宿主自己的定义也能当一段用：传 `selfDef` 即可（总览就是这么做的，
  它既是宿主又是第一段，省掉一次自 require）

**为什么要带前缀而不是留裸名字**：两个模块都有 `add` / `remove` / `toggle`，
裸名字只能属于其中一个，另一个模块内部调用就会串台 —— 这类 bug 很难查。

**WXML 怎么生成**：合并页的模板由 `tools/prefix-wxml.js` 从原页面生成
（根标识符统一加模块前缀），外层只负责画分段控件。手写容易漏改绑定，
改完页面记得重新生成一次。

## 旧的独立页面还在

`pages/todos`、`pages/assignments`、`pages/diet`、`pages/run`、`pages/health`、
`pages/today` 仍然注册在 `app.json` 里，单独打开也能正常工作（已验证）。

保留它们是为了不让旧链接变死链：已经发布过的版本、用户从「最近使用」、
或者别的页面里写死的跳转路径，都可能直接打开这些地址。

它们同时也是合并页的子模块来源 —— 每个文件末尾都有
`module.exports = DEFINITION;`，`tabHost` 靠它拿到页面定义。
所以**不要删这几个文件**，删了合并页会直接报错。

> 注意：`pages/today` 已经不是 tabBar 页了。任何指向它的跳转必须用
> `wx.navigateTo`；写成 `wx.switchTab` 会**静默失败**（不报错，就是不跳）。
> 同理反过来的错误也一样 —— `switchTab` 打不开非 tabBar 页。

## 跳转到合并页的指定分段

`wx.switchTab` 的 url **不能带 query**（带了会跳转失败），所以「打开健康页并
停在运动」这种需求只能：

1. 把 `{ url, seg }` 写到 `app.globalData.pendingSeg`
2. `switchTab` 过去
3. 目标页在 `onShow` 里取走并清除

总览的指标卡和「全部功能」格子都是这么做的（`goStat` / `goTab`）。

分段内容在 `<block wx:if="{{seg === 'xxx'}}">` 里，没有显示的那几段不在渲染树上，
所以子模块的 `onReady`（画 canvas 图表写在里面）不能在宿主 `onReady` 时统一跑，
必须等那一段真的显示出来 —— `tabHost` 用 `_segReady` + `_revealSeg` 做延迟初始化。
`tools/selftest.js` 的 `[14]` 就是这条的回归用例。

## 分段结构的一个坑（写预览工具时踩过）

合并页只有第一段写 `wx:if`，后面的段写 `wx:else`。
`tools/preview-pages.js` 要按分段单独出图，这里的顺序很讲究：

1. 分段过滤必须排在 `dropElseBlocks` **之前** —— 否则第二段（`wx:else`）
   已经被整块删掉了；
2. 也必须排在 `{{...}}` 占位替换**之前** —— 否则条件里的 `seg === 'xxx'`
   已经变成占位符，匹配不上；
3. 选中 `wx:else` 那一段时，还要把这个 `wx:else` 一起改掉，
   不然紧接着的 `dropElseBlocks` 又把它删了，预览就是一片空白。

三个坑都实际踩过一遍，所以在这里记一笔。
